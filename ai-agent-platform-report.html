AI Agent Engineering Platform

Nền tảng AI Agent nhận tài liệu yêu cầu, tự phân tích codebase, lập kế hoạch, viết code, build, test, tự sửa lỗi và báo cáo — được quản lý qua trang quản trị có workflow kéo thả, approval và theo dõi realtime.

Ngày lập: 04/11/2026 Nguồn: ai-agent-platform-roadmap.md Thời lượng ước tính: ~10 tuần cho MVP đầy đủ

01Tóm tắt ý tưởng

Ba lớp tách biệt, một nguyên tắc xuyên suốt: agent phải làm được việc thật trước khi xây nền tảng quanh nó.

Mục tiêu ngắn hạn

Coding Agent MVP

Một lệnh CLI nhận repo + requirement, tạo branch riêng, code, build/test, tự fix tối đa 3 vòng, xuất diff và báo cáo Markdown.

Mục tiêu dài hạn

Nền tảng quản trị

Quản lý nhiều project, job, agent, prompt; thiết kế workflow kéo thả; theo dõi log realtime; duyệt kế hoạch / merge.

Nguyên tắc điều khiển

Engine điều phối, LLM thực thi

Workflow Engine quyết định luồng; AI chỉ làm việc trong từng node → dễ kiểm soát, debug và tính chi phí.

03Đánh giá & điều chỉnh đề xuất

Roadmap gốc có hướng đi đúng. Dưới đây là các điều chỉnh nhằm giảm rủi ro và tránh phải viết lại ở phase sau.

1. Dùng git worktree cho mỗi job

Thay vì checkout branch trong repo gốc. Không đụng working tree của developer, nhiều job chạy song song không xung đột — ngay cả khi chưa có Docker.

2. Build/Test do Python chạy

Exit code thật từ subprocess mới đáng tin. Agent chỉ đọc log lỗi để sửa, không tự báo "đã pass".

3. Bộ task mẫu (eval) ngay từ Phase 1

5–10 task chuẩn để đo tỉ lệ thành công, số vòng fix, chi phí. Không đo được thì không biết agent đã "tin cậy" chưa.

4. Lưu trạng thái job dạng file từ đầu

.ai-jobs/<id>/state.json + events.jsonl ánh xạ thẳng sang bảng jobs, execution_logs, artifacts; hỗ trợ resume.

5. Chốt giao tiếp .NET ↔ Python sớm

CLI + job-file JSON vào, event JSONL ra. Phase 3 chỉ cần "bọc" runtime, không viết lại.

6. Xác thực bằng API key

Worker dùng ANTHROPIC_API_KEY. Đăng nhập Claude Pro chỉ dùng thử cá nhân — đúng cảnh báo trong tài liệu gốc.

Về thời gian: lịch 6 tuần của bản gốc khá lạc quan. Phase 1 thực tế cần ~2 tuần để ổn định vì phần tinh chỉnh prompt và fix loop chiếm nhiều thời gian nhất. Lộ trình bên dưới đã điều chỉnh thành ~10 tuần.
Môi trường hiện tại: Python 3.11, Git 2.43, .NET 10, Claude Code 2.1 đã có. Docker chưa cài — cần trước Phase 5.

06Phase 2 – 6

Phase 2 · ~1 tuần

Multi-Agent

Tách vai trò (subagent hoặc lời gọi riêng) với system prompt và tool riêng. Thêm Review Agent chỉ đọc → {pass, issues[]} → Fixer → Test. Chuyển pipeline cứng thành workflow JSON do Python engine đọc. Chạy lại eval; chỉ giữ multi-agent nếu tốt hơn.

Phase 3 · ~2 tuần

Management Backend

ASP.NET Core + EF Core + PostgreSQL theo schema gốc, bổ sung workflow_versions, cột cost/token, FK/index. Job dispatcher (hosted service) gọi runtime và đọc event vào DB. API Projects/Jobs/Executions/Logs/Artifacts/Approvals, SignalR realtime. Chốt Temporal hay custom cuối phase.

Phase 4 · ~2 tuần

Frontend & Workflow Builder

React + Ant Design + React Flow. Làm Jobs list và Job Detail (timeline, log realtime, diff, Approve/Reject) trước, sau đó Builder: 9 loại node, panel thuộc tính, validate (Start/End, không node mồ côi, vòng lặp có giới hạn), lưu thành phiên bản mới.

Phase 5 · ~1–2 tuần

Docker Sandbox & Worker

Image runtime (Python + SDK + CLI + toolchain .NET/Node). Mỗi job một container: không --privileged, giới hạn CPU/RAM/timeout, user non-root, network egress chỉ tới Anthropic API + registry. Không mount Docker socket, không đưa credential Git vào container. Concurrency theo quota API.

Phase 6 · liên tục

Monitoring & Evaluation

Dashboard từ DB (job, tỉ lệ pass, số vòng fix, chi phí). Prometheus/Grafana cho worker. Eval suite chạy định kỳ, chấm theo tiêu chí chất lượng: đúng phạm vi, đúng convention, không làm hỏng chức năng cũ, mức độ người phải sửa lại.

Quyết định kiến trúc

Mặc định đề xuất

Hàng đợi: bảng DB trước, RabbitMQ khi cần scale. Orchestration: state machine tự viết đến hết Phase 3, đánh giá Temporal khi pause/resume/approval phức tạp. RAG: chưa cần. Deploy tự động: không — luôn qua approval.
